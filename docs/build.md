# Build and test

The host only needs **Docker**. No toolchain — gcc, gbdk, devkitARM,
BlocksDS — is installed locally. The root `Makefile` builds and runs the
matching container for each target and volume-mounts the repo at `/src`.

## Targets

| `make …`   | What it does                                                               | Container         |
|------------|----------------------------------------------------------------------------|-------------------|
| `test`     | Runs every Unity test for every generation                                 | `pksave-test`     |
| `test-gba` | Runs the headless mGBA/Lua automation suite for the Gen III editor         | `pksave-test-gba` |
| `test-tools` | Runs the pure-Python sprite extraction and lookup-generator tests        | none              |
| `gbc`      | Reserved for `bin/pksave-gbc.gbc`; the frontend is still a placeholder     | `pksave-gbc`      |
| `gba`      | Builds the implemented Gen III editor as `bin/pksave-gba.gba`              | `pksave-gba`      |
| `nds`      | Reserved for `bin/pksave-nds.nds`; the frontend is still a placeholder     | `pksave-nds`      |
| `all`      | `test` + `test-tools` + `gbc` + `gba` + `nds`                              | all platforms     |
| `clean`    | Removes generated ROMs, test binaries, and the host shared library         | none              |

Each Docker image is built on first use and cached afterwards.

## Containers

- **`docker/test`** — Ubuntu 24.04 + `gcc` + Unity 2.6.0 (downloaded from
  ThrowTheSwitch). Compiles `libpksave/src/*.c` with all five
  `-DPKSAVE_GENx` flags and runs each `tests/test_genN` binary in turn.
  `make test` exits non-zero on the first failure.
- **`docker/gbc`** — Ubuntu 24.04 + gbdk-2020 4.3.0.
  Compile flags: `-DPKSAVE_GEN1 -DPKSAVE_GEN2`.
- **`docker/gba`** — `devkitpro/devkitarm:latest` + butano 18.5.0.
  Compile flags: `-DPKSAVE_GEN3`. The C++ frontend compiles libpksave's C
  sources into the Butano build and accesses them through a small bridge.
- **`docker/nds`** — `ghcr.io/blocksds/sdk:latest`.
  Compile flags: `-DPKSAVE_GEN4 -DPKSAVE_GEN5`.

All containers volume-mount the repo root at `/src`. Output goes to
`/src/bin/`. Source files are never copied into the image, so iterating
on code does not require an image rebuild.

## Tests

```sh
make test
```

Each test binary follows the same pattern, defined per-generation in
`libpksave/tests/test_genN.c`:

1. Load fixture `.sav` from `tests/fixtures/`
2. Assert known trainer name / TID / SID / money / badges
3. Read party slot 0; assert species, level, first move
4. Mutate a trainer field → `pksave_flush` → reload → assert mutation
   persists
5. `pksave_validate_checksum` returns OK after every flush

Fixtures are **synthetic**, generated by
`libpksave/tests/fixtures/generate_fixtures.py` and committed alongside
the `.sav` files. The script is the single source of truth for the
expected values; the test files assert against the same constants the
generator wrote.

To regenerate fixtures from the host (after editing the generator):

```sh
make -C libpksave fixtures
```

## CI

`.github/workflows/ci.yml` runs on every push to `main` and every PR:

1. **lint-docker** — hadolint over all four Dockerfiles
   (`.hadolint.yaml` configures the rules).
2. **lint-c** — cppcheck over `libpksave/src/` with all five
   `-DPKSAVE_GENx` flags. `--error-exitcode=1`, so warnings fail CI.
3. **lint-python** — ruff over the fixture generator.
4. **test-libpksave** — builds the `pksave-test` image (with GitHub
   Actions cache) and runs the full Unity suite.

The cross-compiled frontend ROMs and mGBA automation suite are not part of the
current GitHub Actions workflow; CI currently gates the portable library and
support tooling. See [frontends.md](frontends.md) for platform status.
